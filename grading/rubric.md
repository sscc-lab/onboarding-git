# 1회차 실습 평가표

`README.md`의 실습 1 · 실습 2를 제대로 마쳤는지 **GitHub에 남은 기록**으로 확인합니다.
채점하는 사람도, 실습하는 사람도 같은 표를 봅니다 — 실습을 마친 뒤 스스로 점검하는 데 써도 됩니다.

- **한 사람씩** 채점합니다. 두 사람이 한 Repository를 쓰므로, 항목마다 «누가 한 일인가»를 GitHub 아이디로 가립니다.
- 근거는 Issue · Pull Request · Review · Commit · `main`의 파일입니다. 말로 한 것, 내 컴퓨터에만 있는 것은 보이지 않습니다.
- 자동으로 판정할 수 있는 것은 `grading/collect.py`가 판정하고, **글의 내용**(자기소개 · Review 의견)은 AI나 사람이 아래 기준으로 봅니다.

## 점수 매기는 법

| 판정 | 점수 |
|---|---|
| 충족 | 배점 전부 |
| 부분 | 배점의 절반 (홀수는 올림 — 5점이면 3점) |
| 미충족 | 0점 |
| 해당 없음 | 배점 전부 — 상대가 할 일을 안 해서 내가 할 수 없었던 경우 (A1) |

**최종 판정**

| 판정 | 조건 | 다음 할 일 |
|---|---|---|
| 완료 | 70점 이상이고 «미충족» 항목이 없다 | 없음 |
| 보완 | 그 밖의 경우 | «미충족» · «부분» 항목의 근거를 보고 그 단계만 다시 해 온다 |

## 평가 항목 — 합계 100점

### 실습 1 · 자기소개 (75점)

| # | 항목 | 배점 | 충족 | 부분 | 미충족 | 어디서 보나 |
|---|---|---|---|---|---|---|
| I1 | Issue | 5 | 본인이 «작업» 양식으로 Issue를 만들고 Assignees에 자신을 지정했다 | Issue는 있지만 양식 · Assignees 중 빠진 것이 있다 | PR과 연결된 Issue가 없다 | Issues 탭 |
| B1 | Branch 이름 | 5 | `type/#번호-설명`이고 번호가 Issue 번호와 같다 (`feat/#1-intro`) | 형식은 맞는데 번호가 Issue와 다르다 | 형식이 아니다 (`intro`, `bob-branch`) | PR 상단의 Branch 이름 |
| C1 | Commit | 10 | 본인 Commit이 **두 개 이상**이고 모두 `#번호 type: 내용` 형식이다 | 둘 중 하나만 지켰다 | 둘 다 지키지 않았다 | PR의 Commits 탭 |
| R1 | Pull Request 작성 | 10 | 제목이 `[#번호] 내용`(type 없음) · 본문에 `Closes #번호` · Reviewer로 상대를 지정 — 셋 다 | 셋 중 하나나 둘 | 셋 다 빠졌다 | PR 제목 · 본문 · 오른쪽 Reviewers |
| F1 | 자기소개 내용 | 10 | `members/<내 아이디>.md`가 `main`에 있고 칸을 자기 말로 채웠다 **(AI 확인)** | 파일은 있지만 대부분 비었거나 양식 그대로다 | 파일이 `main`에 없다 | `members/` 폴더 |
| V1 | 상대 PR Review | 15 | 상대 PR에 **줄 의견**을 남기고 **Request changes** → 반영 뒤 **Approve** — 셋 다 **(AI 확인)** | 셋 중 하나나 둘 (예: 바로 Approve만) | 상대 PR에 Review가 없다 | 상대 PR의 Files changed · Conversation |
| A1 | 받은 Review 반영 | 10 | 수정 요청 **뒤에** 고친 Commit을 올리고, 의견에 답하거나 Resolve하고, **Re-request review**했다 | 고친 Commit만 올렸다 | 수정 요청을 받고도 고친 Commit이 없다 | 내 PR의 Conversation · Commits |
| M1 | Squash Merge 마무리 | 10 | **본인이** Squash and merge · Branch 삭제 · Issue가 PR로 자동으로 닫힘 — 모두 | 합쳤지만 위에서 빠진 것이 있다 (Create a merge commit을 눌렀다, 상대가 대신 눌렀다 등) | 아직 합치지 않았다 | `main`의 Commit 이력 · Issue 상태 |

### 실습 2 · Conflict (25점)

| # | 항목 | 배점 | 충족 | 부분 | 미충족 | 어디서 보나 |
|---|---|---|---|---|---|---|
| K1 | 내 PR | 10 | `team.md`를 고친 PR을 Issue · Branch · Commit · PR 규칙대로 만들고 합쳤다 (Conflict 해결 Commit 메시지 포함) | 합치지 못했거나 규칙을 어긴 곳이 있다 | 실습 2 PR이 없다 | 실습 2 PR |
| K2 | Conflict 해결 **(조 공동)** | 15 | 나중 PR에서 `main`을 merge해 Conflict를 풀고, `main`의 `team.md`에 표시(`<<<<<<<` · `>>>>>>>`) 없이 정한 팀 이름이 남았다 | 팀 이름은 정했지만 Conflict를 푼 merge Commit이 없다 — 같은 줄을 고치지 않았거나 다른 방법으로 합쳤다 **(사람 확인)** | `team.md`에 Conflict 표시가 남았거나 실습 2 PR이 없다 | 나중 PR의 Commits · `team.md` |

K2는 두 사람이 **같은 점수**를 받습니다. Conflict는 나중에 합친 사람이 풀지만, 남길 이름은 둘이 정합니다.

### 감점

| 항목 | 감점 | 기준 |
|---|---|---|
| `main` 직접 Push | −10 | PR 없이 `main`에 들어간 Commit이 그 사람 이름으로 있다 (Repository를 만들 때 생긴 첫 Commit은 제외) |

## AI 확인 항목의 기준

자동 판정은 «기록이 있는가»만 봅니다. 아래 두 항목은 **내용**을 읽고 판정을 **내릴 수만** 있습니다 — 자동 판정이 «미충족»인 것을 올리지는 않습니다(기록이 없기 때문입니다).

**F1 자기소개 내용**

- 충족: 한 줄 소개 · 관심 있는 분야 · 기대하는 것 중 **두 칸 이상**을 자기 말로 채웠다. 짧아도 괜찮다.
- 부분으로 내림: 칸이 거의 비었다, «ㅇㅇ» · «없음» · «.»처럼 의미 없는 글뿐이다.
- 이름 칸에 실명 대신 별명을 써도 된다. 맨 위 안내 문단이 남은 것은 감점하지 않는다.

**V1 상대 PR Review**

- 충족: 줄 의견이나 Review 본문 가운데 **무엇을 왜 고치면 좋을지** 하나 이상이 구체적이다.
  예: «관심 분야를 한 줄 더 구체적으로 적어 주세요» · «GitHub 아이디 링크가 빠졌어요»
- 부분으로 내림: 의견이 «좋아요» · «ㅇㅋ» · «수정해 주세요»처럼 무엇을 고칠지 알 수 없는 말뿐이다.
- 말투 · 맞춤법은 보지 않는다.

## 채점할 때 지킬 것

- **보고서에 자기소개 내용을 옮겨 적지 않는다.** 이름 · 학번 · 연락처가 들어 있을 수 있다. «칸을 채웠다 · 비었다»만 적는다.
- 채점 결과는 **이 Repository에 Commit하지 않는다.** 개인별 점수는 Repository 밖에 둔다.
- 학생의 Repository에 Comment · Review를 남기는 것은 채점자가 직접 결정한다. 채점 도구는 GitHub에 아무것도 쓰지 않는다.
- 근거는 링크로 남긴다. 판정이 애매하면 «사람 확인»으로 두고 이유를 적는다.
